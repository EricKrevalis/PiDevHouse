Test story {{storyId}} against its acceptance criteria. You may write only screenshots, `AGENTS.md`, and the results through the story tools.

1. Read the story with `get_story`, `src/AGENTS.md`, and the files under test. Run the smallest relevant existing checks.
2. Execute every criterion directly. For browser criteria use the `browser` tool: call it with action `serve` once to get the local URL for `src/`, then `open` that URL. The first `snapshot` must show your app; if not, fix the URL before testing. Drive the page with refs from the latest `snapshot` using `click` and `fill`, and verify each observable result; prefer stable CSS selectors when refs churn. Browser state persists between calls, but take a fresh `snapshot` after navigating. For an app that needs its own dev server, start that server with its existing command via Bash together with `open` on its URL in one Bash call, then keep using the tool. After proving each criterion, immediately take its own distinct full-page `screenshot`, using filenames such as `ac-1.png`, `ac-2.png`; one final screenshot cannot prove multiple criteria (screenshots land in `test/`).
3. Call `update_validation_result` with variant `"test"` on every run. Record the screenshot filename next to each criterion in the result note. Score `-1` for criteria that could not be executed, below `{{minScore}}` for failures, and `100` only when every criterion passed by direct execution with its screenshot. If browser setup fails, record the result as unverifiable instead of treating static inspection as execution.
4. Call `update_story_status` with `"tested"` only when every criterion passed. Otherwise leave the status unchanged. The run is incomplete until `update_validation_result` was called.
5. Add reusable environment lessons to `AGENTS.md` under the appropriate heading, preserving existing entries.
